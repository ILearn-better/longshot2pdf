# LongShot2PDF

把**任意可滚动界面**自动滚动截取、无缝拼接、输出为多页 PDF。

典型场景：在网盘里打开一份 500 多页的 PDF，一次性完整滚下来，存成本地 PDF 文件。

界面里有两个同级功能，顶部导航切换：

| 功能 | 输入 | 输出 | 一句话 |
|---|---|---|---|
| **滚动截长图** | 一块能滚动的区域 | 多页 PDF（无缝连续） | 一次滚到底，500 页也不用管 |
| **连续截图整合** | 一屏一张、彼此无关的截图 | Word 或 PDF（可按顺序排版） | 翻一屏按一下 F9，最后统一调版式 |

## 为什么不用微信长截图

| 维度 | 微信长截图 | 本项目 |
|---|---|---|
| 输出格式 | 一张超长 PNG | 多页 PDF（A4 比例） |
| 拼接精度 | 固定位移，易跨页断连 | 逐帧重叠匹配，零断连 |
| 超长处理 | 过长会被拉伸失真、有上限 | 流式分页，无长度上限 |
| 清晰度 | 二次编码，文字发虚 | 原始像素，JPEG 4:4:4 |

## 三个核心设计

1. **滚动有效性探测**：点击开始后先实测光标位置是否响应滚轮，不响应就直接告诉你，不会白滚一场；同时顺手测出「一格滚轮 = 多少像素」，采集时直接复用。
2. **内容自对齐拼接**：不靠固定位移，用画面的行块签名在全位移范围里找最小残差，滚动量不均匀也不会错位。
3. **流式分页**：内存里永远只保留不到两页。500 页（约 70 万像素高、整图 RGB 需 2.1GB）不会 OOM。

## 两种滚动方式

拼接算法是**纯内容比对**的，它只关心「两张图重叠了多少行」，根本不关心位移是谁造成的。
所以自动和手动只差一件事：**谁产生位移**。

| | 自动（默认） | 手动（`--manual`） |
|---|---|---|
| 谁滚 | 程序每帧投递滚轮 | 你自己滚，程序一帧都不投 |
| 步长 | 按实测 `unit_px` 自动校准 | 你说了算，想滚多少滚多少 |
| 什么时候结束 | 滚到底自动收尾 | 按 ESC / 点停止；或 N 秒没动静 |
| 适用 | 500 页一口气拉完 | 想看两眼再滚、或程序不吃合成滚轮 |

手动模式有三处必须区别对待，都已经处理掉了：

- **不跑探测**。探测会「滚下去再滚回来」验证能不能滚 —— 那等于在你眼皮底下
  把页面动一下，而你此刻可能正握着滚轮，两边一打架必然归位不准。
- **不替你滚回去**。自动模式下某一帧接不上，程序会滚回去再减半步长重试；
  手动模式的位移是你的意图，它只能提示你「往回滚一点」（回滚后能重新接上，一行不丢）。
  连续十几帧还接不上才认账：以当前画面为新起点接续，并明确告诉你中间那段没采到。
- **不恢复光标**。它从没动过光标，采集期间你可能已经自己挪走了，最后再拉回起点纯属添乱。

往上滚不会写错内容：拼接只支持往下追加，回看的那一帧会被忽略并提示你。

## 连续截图整合（第二个功能）

有些内容**根本不能滚动**：PPT、分屏对照的表格、每次只能看清一屏的客户端界面。
这时要的不是「接成一张长图」，而是「一屏一张、按顺序攒成一份文档」。
顶部导航第二个标签页就是干这个的 —— 与滚动截长图**同级并列**。

**怎么用**：翻到要截的那一屏 → 按 **F9**（或点「截取当前屏」）→ 继续翻、继续按 →
全部截完再统一调版式 → 导出 Word 或 PDF。

七个模块的交互与状态：

| 模块 | 交互 | 状态展示 |
|---|---|---|
| 截取范围 | **整屏** / **自定义区域** 二选一；选「自定义区域」时多出区域控件，选「整屏」时整块消失 | 右侧常驻显示「屏幕 1920×1080」，一眼知道抓的是多大 |
| 区域位置 | X / Y 数字框 + **九宫格对齐**（把这块贴到屏幕的角/边/正中，只挪位置不改大小） | 点一下状态行报「区域已贴到 left/top：1344×756 @ (0, 0)」 |
| 区域大小 | 宽 × 高数字框 + **锁定比例**（改宽高自动跟） | 越界的数字会被拉回桌面内，而不是让图被裁掉一半 |
| 输出尺寸 | 按区域原样 / **统一宽度** N px | 同一行即时显示「→ 输出 1200 × 675 px」 |
| 截取 | 按钮 + **全局 F9**（焦点在浏览器上也生效） | 抓取中按钮变「抓取中…」并禁用；每抓一张报「已追加第 N 张（宽×高，框选 900×680）」 |
| 列表 | 自动追加到末尾；点选后「删除选中」，可多选 | 行内带序号 `01. 900×680 14:32:05 · 框选` —— 序号就是文档顺序；摘要行「共 N 张 · 预计 M 页」 |
| 尺寸对齐 | 统一宽度 / 统一高度 / 保持原始 + 目标边长；**输出清晰度** 标准/高清/超清 | 下方即时显示「统一后：1600 × 1200 px」，清晰度旁给出「约 317 dpi」；选「保持原始」时目标边长置灰 |
| 位置对齐 | 水平 左/中/右；排布 每图一页 / 连续排列；页边距、图间距 | 选「每图一页」时图间距置灰（它不参与排版） |
| 扫描效果 | 一个开关 + 强度滑杆 | 关掉时滑杆置灰；预览与导出用同一套算法、固定随机种子，所见即所得 |
| 导出 | 「导出 Word」「导出 PDF」两个按钮 | 导出中两个按钮同时禁用并走进度条；完成后显示「已导出 Word · N 张 · 预计 M 页 · X MB」，「打开文件」变为可用 |

### 整屏还是框选

整屏连拍会把侧边栏、工具栏、滚动条一起收进**每一张**；框一块正文区域，等于在采集时
就把裁剪做掉了，而且每张宽高完全一致，后面的「尺寸对齐」都不用调。

| | 整屏 | 自定义区域 |
|---|---|---|
| 抓什么 | 整个虚拟桌面（多屏合并） | 事先框好的一块，**每张都是同一块** |
| 区域从哪来 | 不用管 | 「框选区域…」拖一下，或直接改 X/Y/宽/高 |
| 适合 | 每屏都是一份完整内容 | 翻页时正文位置固定（阅读器、长列表、文档） |

区域是一组纯数字，可以精确到像素地调：`fit_region` 保证它始终落在桌面内，
`snap_region` 保证对齐只改位置不改尺寸，`output_size` 决定最终交付的图多大。

三个值得说明的细节：

- **为什么面板要自动收起**：截的是整屏，面板留在屏幕上就会被截进每一张图。
  所以抓屏前先把自己最小化、等过 200ms 动画、抓完立刻还原 —— 少等这一步，
  第一张图里就会留着「正在缩小的面板」那道残影。
- **为什么用 F9 轮询而不是热键注册**：面板最小化时 tkinter 收不到按键。
  这里和项目里的 ESC 中断用同一套机制（`GetAsyncKeyState` 查物理键状态），
  焦点在哪都能问到；代价是要自己去做边沿检测和 0.35s 冷却，否则按住不放会连抓。
- **Word 和 PDF 的排版口径不同**：PDF 喂的是**整页画布**，所以页数就是界面上的「预计 N 页」，
  所见即所得；Word 喂的是**单张图**，由 Word 自己排 —— 图片在 Word 里保持可选中、
  可拖动，而不是一张「截图里套截图」的死图。「连续排列」时 Word 的页数由 Word 决定，
  所以界面文案写的是「预计」。
- **清晰度是「少缩」而不是「放大」**：版面尺寸（它在纸上占多宽）和嵌入像素（它带多少像素）
  是两件事。排版只要 1000px 宽，而截图原本有 1440px，那就把 1440px 全塞进去 ——
  纸上的宽度不变，每英寸的像素变多。反过来，原图只有 800px 就绝不假装置成 1600px：
  放大只增加体积，不增加细节。实测同一份版面（6.69in 宽）：
  **标准档 149 dpi → 高清档 215 dpi**（源图 1440px），文件大约 30%。
- **DPI 感知要争最高那一档**：只有 Per-Monitor V2 才能保证「每块屏都按自己的物理像素出图」，
  停在 V1 时跨缩放的副屏上抓到的图会被系统位图拉伸一次 —— 那种「像素偏低、字发虚」
  在后期怎么调都补不回来。

不用开界面也能看效果 —— 一条命令造出三份样例：

```bash
python tools/make_demo.py
```

它会把四张**尺寸各不相同**的合成截图（1440×900 整屏 + 900×680 / 1200×760 / 1100×520
三块框选区域）排成三份文档，用来演示「区域大小不一也能排成一份整齐的文档」，
顺便打印出标准档与高清档的有效 dpi（清晰度提升是算得出来的，不是形容词）：

| 文件 | 说明 |
|---|---|
| `demo/shots_demo.docx` | 每图一页，图片在 Word 里可选中可拖动 |
| `demo/shots_demo.pdf` | 每图一页，页数 = 界面上的「预计 N 页」 |
| `demo/shots_demo_scan.pdf` | 连续排列 + 扫描版效果（强度 55） |

`demo/` 与 `*.pdf` 都在 `.gitignore` 里 —— 仓库只放源码，样例现用现生成。
一次实测输出：标准档 1000px → **149 dpi**，高清档 1440px → **215 dpi**（1.44×）。

## 快速开始

**Windows：双击 `start.bat`**（macOS/Linux：`./start.sh`）。第一次会自建 `.venv` 并装依赖，
装完就出界面；之后每次双击直接进界面，约 1 秒。

不想双击就用统一入口，它和 `start.bat` 是同一套逻辑：

```bash
python run.py                                     # 图形界面：框选 → 一键出 PDF
python run.py --region 100,200,1200,900 --out 长图.pdf
python run.py --select --out 长图.pdf             # 全屏框选后再采集
python run.py --select --manual --out 长图.pdf    # 手动滚：你自己滚，它只负责拼
python run.py --dry-run --region 0,0,1200,900     # 只打印计划，不真截
python run.py --doctor                            # 环境体检
```

`run.py` 只用标准库，不需要先装任何东西。它负责把「环境问题」和「程序问题」分开：

| 你遇到的 | 直接跑会报的错 | run.py 的处理 |
|---|---|---|
| PATH 上的 Python 没依赖 | `No module named 'mss'` | 自动挑出可用的解释器并建隔离环境 |
| 用的是没有 tkinter 的 Python | `No module named '_tkinter'` | 换到带 tkinter 的解释器；换不到就走命令行 |
| Python < 3.9 | `'type' object is not subscriptable` | 启动前拦住，直接说要装哪个版本 |

依赖装到项目自己的 `.venv` 里，**不会污染系统 Python 或 conda base**。
装依赖失败时会打印可复制的镜像命令，不会留下半截环境（`.venv` 用 `--clear` 重建）。

采集过程中按 **ESC** 或点「停止」都会立刻停止，并把已采到的内容导出成半成品 PDF。

点「开始」后**面板会自动最小化**（可在界面上关掉），避免它出现在截取区域里 ——
采集期间任务栏标题会实时显示「帧 N · N 页」，点任务栏图标可随时还原，
按 ESC 也能停。采集结束后面板自动还原并顶到前面。

常用参数（`run.py` 与 `cli.py` 共用同一套参数表）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--manual` | 关 | 手动滚动：程序不投滚轮，你自己滚，它只负责抓帧拼接 |
| `--idle-timeout` | 60 | 仅 `--manual`：多少秒没滚动就自动收尾，0 = 一直等你按停 |
| `--overlap` | 0.15 | 相邻帧重叠比例，低于 0.05 拼接必断（仅自动模式） |
| `--settle-ms` | 180 | 滚动后等待渲染稳定的时间，慢机器/懒加载界面可加大 |
| `--quality` | 85 | JPEG 质量，越大越清晰也越大 |
| `--strip-top` / `--strip-bottom` | 0 | 剔除固定表头 / 底栏的像素数 |
| `--max-pages` | 0 | 页数上限，0 为不限 |

启动器专用参数：`--venv` 强制重建 `.venv`、`--no-install` 只看不装、
`--no-switch` 禁止自动换解释器、`--help` 查看全部。

## 测试

```bash
python tests/run_all.py
```

九套测试全部离线运行，不需要真实鼠标和屏幕（界面那两套需要带 tkinter 的解释器，没有会自动跳过）。`tests/mock_frames.py` 里的
`VirtualScreen` 把「长文档 + 滚动位置」伪装成一块屏幕，因此 500 页场景、
惰性加载、固定底栏、ESC 中断这些现实问题都能在 CI 里反复验收。

`test_paths.py` 覆盖的是「文件存哪、存得成不成」这一层：桌面定位要跟随
OneDrive 重定向、`CON.pdf` 这类保留设备名必须提前拦下（否则写出来是 0 字节）、
超过 260 字符的路径要把 `WinError 206` 翻成「改短一点」、`报告.v2` 不能被
当成后缀吃掉版本号。

连续截图那四套同样不开界面也能验：`test_shots.py` 验几何与滤镜（含「预计页数 == 实际页数」
的 12 组参数交叉验证），`test_export.py` 把 docx 当 ZIP 拆开数图片和分页符、用 pypdf 读回 PDF 页尺寸，
`test_shots_panel.py` 则真的建一个 Tk 窗口、把抓屏和文件对话框换成桩，像用户一样点按钮。

## 已知边界

| 情况 | 表现 | 应对 |
|---|---|---|
| 区域里有固定表头/底栏/悬浮按钮 | 重叠区永远对不上，采集停止并提示 | 用 `--strip-top` / `--strip-bottom` 剔除 |
| 一格滚轮就是一整屏（部分 PDF 阅读器） | 重叠为 0，数学上无法拼接 | 明确提示把框选高度调到半屏 |
| 滚动区域里有视频/动画 | 指纹被污染 | 框选时避开，或加大 `--settle-ms` |
| 高 DPI（125%/150%） | 坐标错位 | 已争到 Per-Monitor V2，全程物理像素 |
| 框选区域跨两块屏、或拖到屏幕外 | 越界部分抓不到 | 抓前自动裁剪进桌面，位置类编辑会自动贴边 |
| 框选区域比导出所需还小 | 「超清」档也不会更清晰 | 界面会标「已用满原图像素」；想更清晰只能把框框大或提高系统缩放 |
| 系统缩放 100% 时框选 900px 宽 | 统一到 1200px 是插值放大 | 放大不增加细节，交付时按实际像素用即可（选「按区域原样」） |
| 扫描效果的颗粒 | JPEG 压不动高频噪声，体积比彩色版大 5%~20% | 觉着大就调低强度；这是「扫描件」的代价，不是 bug |
| 连续截图删掉中间一张 | 文档顺序跟着前移（序号重排） | 序号就是文档顺序，删完看一眼序号即可 |
| 导出文件名撞上 `CON` / `PRN` / `COM1` 这类保留设备名 | 系统会把它当设备，写出来是 0 字节空壳 | 导出前预检直接拦下；万一漏过去，0 字节也会报错而不是说「已导出」 |
| 输出路径超过 260 字符 | `WinError 206 文件名或扩展名太长` | 报错会说明「改短或开启长路径支持」，不再只吐原始错误码 |
| 桌面被 OneDrive 重定向到 `~/OneDrive/Desktop` | 默认导出位置跟着走 | 用 Windows 已知文件夹定位，不再硬猜 `~/Desktop` |
| 文件名写成 `报告.v2` | 保留版本号：`报告.v2.pdf` | 只有 `.pdf`/`.docx` 这类格式后缀才会被替换 |

## 环境

Python 3.9+ · `mss` `numpy` `Pillow` `img2pdf`（`pypdf` 仅测试用）。
需要带 tkinter 的 CPython 才能开界面；没有也能用命令行。

### 实测过的组合

| Python | 依赖 | 结果 |
|---|---|---|
| 3.11.4 | **下限组合**：mss 10.0.0 · numpy 1.26.4 · Pillow 10.1.0 · img2pdf 0.5.1 | 九套全绿（含界面两套），62s |
| 3.11.4 | mss 10.2 · numpy 2.0 · Pillow 10.3 · img2pdf 0.6.3 | 九套全绿（含界面两套），60s |
| 3.13.14 | mss 10.2 · numpy 2.5 · Pillow 13.0 · img2pdf 0.6.3 | 九套全绿（界面两套因无 tkinter 跳过），49s |
| 3.9 | — | 语法与运行时特性静态检查通过（本机无 3.9 解释器，未实跑） |

依赖只钉下限（`mss>=10.0` 这类），所以 numpy 1.26→2.5、Pillow 10→13 都能装；
代码里没有用到 numpy 2.0 移除的别名（`np.float_` / `np.int0` …），
也没有 Pillow 10 移除的 `Image.ANTIALIAS` / `textsize`，跨这个大版本区间是安全的。

### 跨平台

- **Windows**：全部功能可用。滚轮投递、全局按键（ESC / F9）、Per-Monitor V2 DPI
  都是 Win32 调用，这是项目的目标平台。
- **macOS / Linux**：`start.sh` 能启动、界面能开、导出 Word/PDF 正常。
  采集侧靠 mss（X11 / macOS 需授予屏幕录制权限），**自动滚动与 F9 不可用**
  （`winapi` 的 user32 不存在，投递滚轮会抛 OSError）。
  手动滚（`--manual`）可跑：位移由你自己滚，拼接算法与平台无关，
  ESC 轮询退化为不可用，用 `--idle-timeout` 或「停止」收尾。
  屏幕尺寸在非 Windows 上改问 `mss.monitors[0]`，不再被钉死在 1920×1080。

导出 Word **不需要 python-docx**：`src/docxwriter.py` 直接拼 OOXML（ZIP + XML），
所以没有 lxml 这个 C 扩展依赖 —— 那条路在没装编译器的 Windows 上正是最容易断的一环。

先体检再排查：`python run.py --doctor` 会把「机器上有哪些解释器、各自缺什么、
能不能截屏、Tk 能不能建窗口」一次列清。
